* Fish Shell Configuration
:PROPERTIES:
:ID:       e853361b-1423-4531-a381-28d974cdbf2b
:END:
This document outlines my personal configuration for the Fish shell (Friendly Interactive SHell). It's
written using Org Mode for literate programming, allowing configuration code and documentation to coexist
seamlessly. The setup automatically tangles the code blocks into a usable =config.fish= file located in
the appropriate Fish configuration directory whenever this Org file is saved in Emacs (see [[Setting Up Auto-Tangle][Setting Up
Auto-Tangle]] section).

The primary goal is to create a productive, visually informative, and customized shell environment.

- [[https://github.com/oh-my-fish/oh-my-fish][Oh my fish!]]: While not explicitly used for managing plugins here (Fisher is preferred), the ecosystem

  prompts.

*** Syntax Highlighting
The syntax colors live in =themes/rogs.theme=. It has a dark and a light variant, and fish picks the one
that matches the terminal's background (=fish_terminal_color_theme=), so it switches together with
Ghostty. Terminals that don't report their background get the dark colors.
#+begin_src fish
# Load the rogs syntax highlighting theme (themes/rogs.theme)
if status is-interactive
    fish_config theme choose rogs
end
#+end_src

*** Tide Prompt
Tide keeps its colors in universal variables, because it draws the prompt in a background fish process
that only sees universal variables. =rogs_tide_colors= sets them all. Run it once, and again after
=tide configure=, which resets the colors. Tide has no light variant, so these are the dark colors.

The left side uses colored segments with dark text: the vi mode, the OS icon on a dark segment, the path
in blue, and git in green, yellow when there are changes, or red when something needs attention. The
right side uses dark segments with colored text, apart from a red segment when the last command failed.
#+begin_src fish :tangle functions/rogs_tide_colors.fish
function rogs_tide_colors --description 'Set the tide prompt colors to the rogs palette'
    set -l dark 0A0A0A
    set -l raised 1E1E1E

    # Vi mode: blue for normal, green for insert, red for replace, purple for visual
    set -U tide_vi_mode_bg_color_default 6BA1E6
    set -U tide_vi_mode_bg_color_insert 50FA7B
    set -U tide_vi_mode_bg_color_replace E06C75
    set -U tide_vi_mode_bg_color_visual BDABF0
    set -U tide_vi_mode_color_default $dark
    set -U tide_vi_mode_color_insert $dark
    set -U tide_vi_mode_color_replace $dark
    set -U tide_vi_mode_color_visual $dark

    # OS icon in green on a dark segment
    set -U tide_os_bg_color $raised
    set -U tide_os_color 50FA7B

    # Path in blue
    set -U tide_pwd_bg_color 6BA1E6
    set -U tide_pwd_color_anchors $dark
    set -U tide_pwd_color_dirs $dark
    set -U tide_pwd_color_truncated_dirs 18355B

    # Git: green when clean, yellow with changes, red for conflicts and operations
    set -U tide_git_bg_color 50FA7B
    set -U tide_git_bg_color_unstable E5C07B
    set -U tide_git_bg_color_urgent E06C75
    for v in branch conflicted dirty operation staged stash untracked upstream
        set -U tide_git_color_$v $dark
    end

    # Prompt character, frame and separators
    set -U tide_character_color 50FA7B
    set -U tide_character_color_failure E06C75
    set -U tide_prompt_color_frame_and_connection 4C4C4C
    set -U tide_prompt_color_separator_same_color 808080

    # Status: green check on a dark segment, red segment when the last command failed
    set -U tide_status_bg_color $raised
    set -U tide_status_color 50FA7B
    set -U tide_status_bg_color_failure E06C75
    set -U tide_status_color_failure $dark

    # Right side: dark segments with colored text
    set -U tide_cmd_duration_bg_color $raised
    set -U tide_cmd_duration_color E5C07B
    set -U tide_context_bg_color $raised
    set -U tide_context_color_default B5B5B5
    set -U tide_context_color_root E06C75
    set -U tide_context_color_ssh E5C07B
    set -U tide_jobs_bg_color $raised
    set -U tide_jobs_color 56B6C2
    set -U tide_time_bg_color $raised
    set -U tide_time_color B5B5B5
    set -U tide_shlvl_bg_color $raised
    set -U tide_shlvl_color E5C07B
    set -U tide_private_mode_bg_color $raised
    set -U tide_private_mode_color EEEEEE
    set -U tide_direnv_bg_color $raised
    set -U tide_direnv_color E5C07B
    set -U tide_direnv_bg_color_denied E06C75
    set -U tide_direnv_color_denied $dark

    # Languages and tools, each in the palette color closest to its brand color
    for pair in aws:D19A66 bun:EEEEEE crystal:EEEEEE distrobox:BDABF0 docker:6BA1E6 elixir:BDABF0 \
            gcloud:6BA1E6 go:56B6C2 java:D19A66 kubectl:6BA1E6 nix_shell:6BA1E6 node:50FA7B \
            php:BDABF0 pulumi:E5C07B python:6BA1E6 ruby:E06C75 rustc:D19A66 terraform:BDABF0 \
            toolbox:BDABF0 zig:D19A66
        string split : $pair | read -l -L item color
        set -U tide_"$item"_bg_color $raised
        set -U tide_"$item"_color $color
    end

    tide reload
end

** Secrets
:PROPERTIES:
:ID:       5b3f2b1a-4c99-4a11-9f2e-4e1c9a5a0f01
:END:
Environment variables that contain API keys or other secrets live in =~/.config/fish/conf.d/secrets.fish=.
Fish auto-sources every =*.fish= file in =conf.d/= at startup, so variables defined there are exported to
every shell session (and any process the shell spawns, such as opencode). The file is listed in
=.gitignore= so secrets are never committed to the dotfiles repository. Copy
=conf.d/secrets.fish.example= to =conf.d/secrets.fish= and fill in your values; do not commit the real
file.

* Setting Up Auto-Tangle
:PROPERTIES:
:ID:       b080b2cc-8841-4ee5-8c1c-e39588e9f7b6
:END:

This configuration file uses Org Mode's literate programming capabilities. To automatically generate the
=config= file needed by Polybar every time this =.org= file is saved in Emacs, you need to add the
following Elisp code to your Emacs initialization file (e.g., =~/.emacs.d/init.el=). This code defines a
function `org-babel-auto-tangle` and adds it to the `after-save-hook`. When an Org file is saved, this
function checks for the `#+auto_tangle: t` property at the beginning of the file and, if found, runs
`org-babel-tangle` to generate the output file(s) (in this case, =config=).

#+begin_src emacs-lisp :tangle no
;; Auto-tangle configuration files
(use-package org
  :config
  (defun org-babel-auto-tangle ()
    "Automatically tangle org files when saved if they have '#+auto_tangle: t'."
    (when (eq major-mode 'org-mode)
      ;; Check for the #+auto_tangle property in the Org file
      (let ((auto-tangle (cdr (assoc "auto_tangle" (org-collect-keywords '("PROPERTY"))))))
        ;; If the property exists and is set to "t", tangle the file
        (when (and auto-tangle (string= auto-tangle "t"))
          (org-babel-tangle)))))
  ;; Add the function to the 'after-save-hook' to run it after every save
  (add-hook 'after-save-hook #'org-babel-auto-tangle))
#+end_src
